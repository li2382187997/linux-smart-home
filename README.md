# 嵌入式 Linux 智能家居控制终端 · Smart Home Terminal

项目背景：**学校组织的企业实训**（中科（安徽）康芯科技有限公司）。
在嵌入式 Linux 开发板上用**纯 C** 写出一套智能家居中控界面：800×480 电阻触摸屏、帧缓冲直绘 UI，串起「嵌入式中控 + STM32 从机 + Ubuntu 语音识别」三层。

> 12 张屏幕实拍与演示视频见 [`media/`](media/)；早期设计文稿见 [`docs/overview.md`](docs/overview.md)。

## 系统架构

| 层 | 硬件 | 职责 | 通信方式 |
|---|---|---|---|
| 人机交互层 | 嵌入式 Linux 开发板（800×480 电阻触摸屏） | 界面绘制、触摸分发、页面状态机 | — |
| 传感执行层 | STM32 从机 | 3 路 LED、血压模块、心率模块 | 串口 `/dev/ttySAC2` |
| 智能服务层 | Ubuntu 服务器 | 语音识别：PCM 上传 → 返回命令码 | TCP socket |

运行方式：`./app <ubuntu-IP>`。启动后依次完成串口、语音 socket、LCD、触摸屏初始化，
走完「欢迎页 → 开机进度条」进入主界面事件循环。

## 页面结构

主界面是四个卡片入口，点击进入对应页面，每个页面独立循环、设有「返回」热区，退出后回到主页：

```
start()     欢迎页        → loading()  开机进度条 → page_main()  主页
                                                    ├─ 相册     gallery()
                                                    ├─ 语音控制 voice()
                                                    ├─ 留言器   recorder()
                                                    └─ 灯光控制 light()
```

## 四大功能

### 1. 语音控制（核心链路）

点麦克风 → 采集并上传 PCM → Ubuntu 侧识别 → 返回命令码 `id` → 解析执行。

| 命令码 | 动作 |
|---|---|
| 2 | 打招呼，屏显「你好！」 |
| 3 | 测血压：向 STM32 发 `mks-sbp`，屏显 `血压：xx mmHg` |
| 4 | 跳转相册页 |
| 5 | 跳转留言器页 |
| 6 | 测心率：向 STM32 发 `mks-hr`，屏显 `心率：xx bpm` |
| 100 | 全开灯光：`led1-on/led2-on/led3-on` |
| 其他 | 「抱歉，我好像没听懂，请再说一遍」 |

### 2. 相册

本地轮播 4 张 BMP（0720 / 07 / 06 / 10），底部导航「下一张」循环切换、「返回」退出。

### 3. 留言器

调用录音脚本录 5 秒音频，保存后再调用播放脚本回放，充当家庭留言板。

### 4. 灯光控制

屏幕三色灯块（红 / 绿 / 蓝）点击切换开关状态，向下位机发送 `ledN-on` / `ledN-off` ASCII 命令，
同屏状态实时反映（亮色 block = 开，灰色 block = 关）。

## 底层实现

### 界面：像素一站式自绘

没有用任何 GUI 框架，所有图元都在 `src/main.c` 里手写：

- `draw_solid_rect()` / `draw_hline()` / `draw_frame()` / `draw_progress()` —— 纯色块、横线、边框、进度条
- 直接按 `(y * 800 + x) * 4` 偏移写 ARGB 像素到帧缓冲，出屏坐标自动裁剪
- 中文/写字依赖 BSP 封装的 FreeType 接口（`fontLoad` / `fontSetSize` / `fontPrint` / `show_font`），
  `draw_text_center()` / `draw_text_left()` 在此之上做了排版封装

### 自写 24 位 BMP 解码器

实训方例程自带的解码函数对 24 位图支持不全，所以自己写了 `show_24bmp()`：

- 只接受 24 位 BMP，读 54 字节头解析宽高与位深，非 24 位直接报错退出
- 逐像素 `BGR → ARGB`（含 alpha 置 0xFF）
- 按 4 字节补齐行尾 padding
- BMP 行是**自下而上**存储的，写帧缓冲时做了垂直翻转
- 支持 `x0/y0` 偏移绘制，超出屏幕的部分裁剪

配套两个容错封装：文件缺失时 `show_image_full()` / `show_image_at()` 会画出带文件名的占位块，
而不是留一块黑屏让人猜。

### 触摸去抖

电阻屏按下瞬间坐标会漂，直接读会误触。`read_touch()` 的做法是：

- 首次读到点记为「按下」，记下时间与坐标
- 之后持续采样，**同时**满足「位移 < 24 px」且「距按下不足 20 ms」的点全部丢弃
- 位置稳定或超出抖动窗口后才上报坐标

参数集中在开头两个宏里，方便按屏体质调整：

```c
#define TOUCH_JITTER_MS 20  // 抖动时间窗口
#define TOUCH_LOCK_DIST 24  // 位移阈值（像素）
```

### 串口可靠查询

血压/心率这类测量命令发出后要等 STM32 回数。`stm_query()` 的处理：

- 发命令前先读干接收缓冲，避免上一条残留数据干扰
- `poll()` 200 ms 超时轮询，累计到 `wait_secs` 秒
- 逐字节攒进缓冲，遇到数字/换行即成帧返回，超时返回 -1

## 关于可编译性（务必先读这段）

`src/main.c` 是 **692 行的单文件主程序**，包含本项目的全部应用层实现。
但实训方提供的板级支持代码**不在仓库内**：

- `common.h` / `common.c` — 板级 BSP，提供 `lcd_init()`、`ts_init()`、`init_tty()`、`init_sock()`、
  `get_xy()`、`get_voice_info()`、`wait4id()`，以及字体渲染接口（**版权属实训方**）
- 字库文件与 `home/*.bmp`、`bj.bmp`、`bj2.bmp` 等图片素材 —— 运行期资源
- `recordcmd.sh` / `myplay.sh` 录音播放脚本、交叉编译工具链、NFS 挂载环境

所以**仓库单独 clone 下来无法直接编译**。
可以读的部分包括：页面状态机、图元绘制、24 位 BMP 解码、触摸去抖、串口协议解析、语音命令分发。
